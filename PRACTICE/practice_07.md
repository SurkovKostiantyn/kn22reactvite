## 2. Аналіз та Декомпозиція

В рамках практичної роботи №7 було реалізовано динамічну маршрутизацію та роботу з параметрами URL.

### Структура компонентів:

1. **`Practice7` (Контейнер):**
   - Виступає як батьківський компонент для сторінок практики. Використовує `<Outlet />` для рендерингу вкладених маршрутів.
2. **`NewsFeed` (Smart-компонент):**
   - Використовує хук `useSearchParams` для синхронізації стану пошуку та сортування з адресою сторінки.
   - Реалізує динамічну фільтрацію масиву даних на основі параметрів запиту (`?query=...`).
   - Реалізує сортування елементів (за алфавітом та у зворотному порядку) через параметр `?sort=...`.
3. **`PostDetails` (Smart-компонент):**
   - Використовує хук `useParams` для отримання унікального `postId` з URL-шляху (`/post/:postId`).
   - На основі отриманого ID знаходить та відображає деталі конкретного поста.

### Реалізований функціонал:
- **Динамічні посилання**: Кожен пост у списку є посиланням на свою сторінку детального перегляду.
- **Синхронізація з URL**: При зміні тексту в полі пошуку або зміні сортування, URL-адреса оновлюється автоматично. Це дозволяє зберігати стан при перезавантаженні сторінки.
- **Комплексна обробка даних**: Дані спочатку фільтруються за пошуковим запитом, а потім сортуються згідно з обраним порядком.

## 3. Контрольні запитання

1. **Поясніть принципову різницю між URL-параметрами шляху (Path Parameters, наприклад /users/42) та параметрами запиту (Query Parameters, наприклад /users?sort=asc). В яких випадках який підхід слід використовувати?**
   - **Path Parameters** використовуються для ідентифікації конкретного ресурсу (наприклад, конкретного користувача або поста). Вони є частиною ієрархічної структури URL.
   - **Query Parameters** використовуються для модифікації вигляду або набору даних (фільтрація, сортування, пагінація). Вони не змінюють сам ресурс, а лише те, як ми його бачимо.

2. **Що робить хук useParams() і який обов'язковий синтаксис необхідно використати в визначенні <Route path="..."> для того, щоб цей хук запрацював?**
   - `useParams()` повертає об'єкт з парами ключ/значення динамічних параметрів поточного URL, які були визначені у `<Route>`.
   - Обов'язковий синтаксис: використання двокрапки перед назвою параметра у шляху, наприклад: `<Route path="post/:postId" ... />`.

3. **Чому зберігання стану пошукового рядка (Search Bar) в URL (через useSearchParams) вважається архітектурно кращим рішенням, ніж зберігання його у локальному стані компонента (useState)? Опишіть переваги для кінцевого користувача.**
   - Це дозволяє користувачеві ділитися посиланням на конкретні результати пошуку.
   - Стан зберігається при перезавантаженні сторінки або при навігації "Назад"/"Вперед" у браузері.
   - Це робить поведінку додатка більш передбачуваною та стандартною для веб-середовища.

4. **Якщо ви використовуєте метод масиву filter() прямо перед поверненням JSX-розмітки, чи відбувається ця фільтрація при кожному рендері компонента? Як це може вплинути на продуктивність для дуже великих масивів (напр. 10 000+ елементів) і який інший React-хук ви б використали для оптимізації?**
   - Так, фільтрація відбувається при кожному рендері.
   - Для великих масивів це може призвести до "гальмування" інтерфейсу, оскільки важка операція виконується часто.
   - Для оптимізації слід використовувати хук `useMemo`, щоб кешувати результати фільтрації та сортування і перераховувати їх лише тоді, коли змінюються вхідні дані або параметри фільтрації.

5. **В яких об'єктах стандарту Web API у звичайному (базовому) JavaScript зберігаються параметри після знаку питання ?, і як React Router спрощує роботу з ними?**
   - У базовому JS параметри доступні через `window.location.search`. Для зручної роботи використовується об'єкт `URLSearchParams`.
   - React Router через хук `useSearchParams` надає зручний інтерфейс (схожий на `useState`), який автоматично оновлює компонент при зміні параметрів і дозволяє легко змінювати їх без ручного маніпулювання рядками URL.
