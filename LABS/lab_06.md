## Фрагменти коду

### 1. API взаємодія (`src/api/cocktailApi.js`)

Для інкапсуляції логіки роботи з API було створено окремий файл з функціями-обгортками над `fetch`:

```javascript
const BASE_URL = 'https://www.thecocktaildb.com/api/json/v1/1';

export const searchCocktailByName = async (name) => {
  const response = await fetch(`${BASE_URL}/search.php?s=${name}`);
  if (!response.ok) throw new Error('Failed to fetch data');
  return response.json();
};

export const listCocktailsByLetter = async (letter) => {
  const response = await fetch(`${BASE_URL}/search.php?f=${letter}`);
  if (!response.ok) throw new Error('Failed to fetch data');
  return response.json();
};

export const getCocktailDetailsById = async (id) => {
  const response = await fetch(`${BASE_URL}/lookup.php?i=${id}`);
  if (!response.ok) throw new Error('Failed to fetch data');
  return response.json();
};

// ... інші методи фільтрації
```

### 2. Компонент з реалізацією життєвого циклу запиту (`Lab6.jsx`)

Компонент `Lab6` реалізує тріаду станів (`loading`, `error`, `data`) для відображення списку коктейлів (Loading стейт, Error стейт, Data стейт):

```javascript
import { useState, useEffect } from 'react';
import { listCocktailsByLetter } from '../../../api/cocktailApi';
import Loader from '../../atoms/Loader';
import CocktailCard from '../../moleculas/CocktailCard';

const Lab6 = () => {
  // Тріада станів
  const [cocktails, setCocktails] = useState([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  // Ініціалізація даних при монтуванні
  useEffect(() => {
    fetchCocktailsByLetter('a');
  }, []);

  const fetchCocktailsByLetter = async (letter) => {
    setLoading(true); // Встановлення стану завантаження
    setError(null); // Очищення попередніх помилок

    try {
      const data = await listCocktailsByLetter(letter);
      setCocktails(data.drinks || []);
      if (!data.drinks) setError('Немає коктейлів на цю літеру');
    } catch (err) {
      setError('Помилка завантаження даних');
    } finally {
      setLoading(false); // Завершення стану завантаження
    }
  };

  return (
    <div>
      {/* Рендеринг залежно від стану */}
      {loading ? (
        <Loader />
      ) : error ? (
        <div className="error">{error}</div>
      ) : (
        <div className="grid">
          {cocktails.map((cocktail) => (
            <CocktailCard key={cocktail.idDrink} cocktail={cocktail} />
          ))}
        </div>
      )}
    </div>
  );
};
```

## Відповіді на контрольні запитання

### 1. Поясніть призначення об’єкта AbortController у нашому хуку useFetch. Яку загрозу для React-додатку він усуває?

`AbortController` дозволяє достроково перервати або скасувати мережевий запит, якщо компонент, що ініціював цей запит, був розмонтований до його завершення (наприклад, користувач швидко покинув сторінку). Це усуває загрозу витоку пам'яті (memory leaks) та запобігає спробам оновлення стейту розмонтованого компонента (`Warning: Can't perform a React state update on an unmounted component`), що призводить до непомітних помилок і погіршення продуктивності додатку.

### 2. Що таке патерн “Тріада станів” (loading, error, data) при роботі з мережею і чому він є обов’язковим для якісного UX?

Патерн "Тріада станів" передбачає трекінг трьох ключових станів під час будь-якого мережевого запиту:

- `loading` (показує користувачеві індикатор завантаження).
- `error` (відображає повідомлення у випадку помилки з'єднання або помилки сервера).
- `data` (зберігає успішно отримані дані для відмальовки інтерфейсу).

Він є обов'язковим для якісного UX, оскільки без нього користувач не отримує зворотного зв'язку від інтерфейсу і може подумати, що додаток "завис", або дивитиметься на порожній екран під час завантаження даних чи виникнення помилок.

### 3. Чому функція виконання мережевого запиту (fetch або axios.get) розміщується всередині хука useEffect, а не прямо в тілі функціонального компонента?

Компоненти React перемальовуються (рендеряться) щоразу при зміні їх стану або пропсів. Якщо розмістити функцію виконання запиту прямо в тілі компонента (без `useEffect`), то запит буде відправлятися при кожному рендері. Це створить небезпечний нескінченний цикл: функція викликається $\rightarrow$ запит відправляється $\rightarrow$ дані приходять $\rightarrow$ стан оновлюється (`setState`) $\rightarrow$ відбувається новий рендер віртуального DOM $\rightarrow$ функція знову викликається.
Хук `useEffect` з порожнім масивом залежностей `[]` дозволяє виконати мережевий запит контрольовано — тільки один раз під час першого монтування компонента.

### 4. У чому полягають головні переваги використання бібліотеки axios у порівнянні з нативним fetch?

1. **Автоматична конвертація в JSON**: `axios` автоматично парсить відповіді у форматі JSON, тоді як при використанні `fetch` потрібно самостійно викликати `await response.json()`.
2. **Краща обробка помилок**: `axios` автоматично відхиляє проміс, якщо HTTP статус відповіді знаходиться поза межами $2xx$ (наприклад, 404 чи 500). З нативним `fetch` потрібно перевіряти `response.ok` та викидати помилку самостійно, оскільки помилка генерується лише при відсутності мережі.
3. **Глобальні Інтерсептори (Interceptors)**: `axios` дозволяє глобально перехоплювати запити або відповіді налаштовуючи їх (наприклад, для ін'єкції Bearer токену в кожен запит).
4. **Вбудоване управління таймаутами**: в `axios` можна зручно встановити таймаут для запитів на відміну від `fetch`, де для цього доводиться використовувати `AbortController`.

### 5. Опишіть потенційні ризики багу “Стан гонитви” (Race Condition), якщо користувач буде дуже швидко перемикати сторінки з різними URL-параметрами, за якими робляться запити.

“Стан гонитви” (Race Condition) трапляється, коли кілька мережевих запитів виконуються паралельно через те, що користувач надто швидко виконує дії (наприклад, клікає різні фільтри або літери), але сервери можуть обробити ці запити з різною швидкістю. В результаті, відповідь на попередній (вже нерелевантний) запит може прийти пізніше, ніж на поточний, і перезаписати стан.
У підсумку, наприклад, при перемиканні фільтра "Безалкогольні" $\rightarrow$ "Алкогольні", на екрані можуть відображатися безалкогольні напої, хоча індикатор у UI показуватиме "Алкогольні". Для вирішення цієї проблеми розробники використовують скасування попередніх запитів (за допомогою `AbortController`) або ігнорують результати старих запитів за допомогою змінних-прапорців.
